# T-200#B-001 画廊行压缩复现与定位

## 现象

在内部 `demo/fixtures/pdf-pagination-row.md` 上扫描填充段，比较 `imageOptimizationEnabled=false` 与 `true`：

| 填充段 | off 第 1 页图片数 | images 第 1 页图片数 | 判定 |
| --- | --- | --- | --- |
| 5.25 | 3 | 3 | 无差异 |
| 5.5 | 3 | 3 | 无差异 |
| 5.75 | 3 | 3 | 无差异 |
| 5.85 | 3 | 3 | 无差异 |
| 5.9 | 3 | 3 | 无差异 |
| 5.95 | 3 | 3 | 无差异 |
| 5.97 | 3 | 3 | 无差异 |
| 5.98 | 3 | 3 | 无差异 |
| 5.99 | 3 | 3 | 无差异 |

对 5.75 与 5.99 的第 1 页做逐像素比较：

```text
k5.75  AE = 0
k5.99  AE = 0
```

即：开启「图片分页优化」后，页面没有任何像素变化；行压缩分支没有改变行盒高度。

## 代码线索

- `runImagePass` 会遍历 `collectImageUnits` 返回的 gallery 单元（`src/pdf-pagination.js:262-301`）。
- `measureImageUnit` 会为 gallery 收集每格 `<img>`（`:442-449`）。
- `applyScale` 对 gallery 只改图片的 `width/height`（`:453-463`），没有同时缩小承载它的画廊行盒。

如果单元格高度由行盒变量或固定 `height` 决定，单独缩图只会裁切，不会让整行变矮，`attemptExactFit` 因此永远判定「放不下」，行被整体下移。这与观察到的「无压缩窗口」一致。

## 下一步（T-200#B-002）

先验证打印 DOM 中 gallery 单元格的高度来源；若确为固定行高，`applyScale` 需要在缩图的同时按同一 `scale` 缩小行盒（及 `--ag-row-height`）。修完必须重新导出 5.99/6.0 并断言出现「off 下移、images 留在页内」的窗口。若设计上不支持，则改文档，撤回「整行同比例缩小」的表述。
