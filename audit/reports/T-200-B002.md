# T-200#B-002 修复尝试与结论

## 已确认的事实

- `attemptExactFit` 确实进入了 gallery 分支：trace 显示 `gallery=true`、`elements=3`、`images=3`、`shrinkMax=0.3`。
- 缩图确实改变行高：30% 缩放下行底从 `1156.5` 移到 `1106.3`，移动 `50.2px`。
- 但行仍然停在第 2 页；`fitsAt` 的 `page <= candidatePage` 始终不成立。

## 试过的三种修法

| 修法 | 结果 |
| --- | --- |
| 计算 deficit 时减去页偏移 | `first.page=2`，减去整页后 deficit 变成负数，直接放弃；行仍下移 |
| 缩放期间把 `.ag-pdf-row` 的 `break-inside` 临时改为 `auto`，缩完恢复 | 行仍下移；页面无变化 |
| 缩放后切换打印根 `display` 强制重排 | 行仍下移；页面无变化 |
| 把上限从 30% 提到 50% | 行仍下移；不是缩得不够 |

## 结论

这不是“缩得不够”或“少减了一个偏移”。Chromium 对 `break-inside: avoid` 的行在**分页决策之后不会因为高度变小而回弹**；`attemptExactFit` 在已经翻页的坐标系里做二分，永远无法把行拉回上一页。

局部补丁无法解决。可行方向只有两个：

1. **重建打印树**：缩图后按新几何重新克隆/重排打印根，让 Chromium 重新做一次分页决策；代价是分页轮次与缓存键要跟着改，属于中等规模改动。
2. **改文档**：承认画廊行只整体换页，不压缩；保留单图压缩与标题分页。这样与当前运行行为一致，S19-01 改为“整行下移、页尾留白”的单版说明或取消该图。

在方向确定前不改 `src/pdf-pagination.js`。三种实验性改动已全部回退，`git diff src/` 为空，`main.js` 已重建并恢复硬链接。

## 进一步：trace 为空

改用 520px 的可调空白块（`pdf-row-spacer.md`）后，510px 时行在第 1 页，520px 时整行到第 2 页，窗口只有 10px。此时打开 trace 导出，`__AG_PAGINATION_TRACE__` 为空：`runImagePass` 根本没有调用 `attemptExactFit`。

这说明根因比“缩图不生效”更早：测量模型认为行**没有被推走**（`residual` 不小于 0），但 Chromium 实际把它打印到了第 2 页。要修的是 `protectGalleryRows` / `rebuildBreakTable` 对流单元高度的识别，而不是 `applyScale` 或 deficit。

下一步应验证：打印树里 `.ag-pdf-row` 是否是 `.markdown-preview-section` 的直接子节点；`flowUnits` 取到的 unit 高度是否包含整行；`isAtomicFlowUnit` 对该 unit 是否返回 true。修好检测后，再回到缩图路径。


## 最终证据：模型判定成功，PDF 仍然换页

在 520px 空白块上打开 flow trace，完整阶段为 `pass → target → attempt → deficit → fit×5`：

```text
target: page 0, available 203, residual 6, anchorBottom 1036, pushed true
attempt: gallery true, elements 3, images 3, imageHeight 197.34, width 672.98
deficit: 4px
fit: shrink 0.0197 → page 0, bottom 1033, pageBottom 1043  （判定成功）
```

按测量模型，缩 1.97% 就已经放得下。但同一份导出 PDF 仍然是 2 页、3 张图全在第 2 页。

结论：`applyScale` 同时写了活 DOM 和测量克隆，但 Chromium 的**最终打印树在分页决策后不会因为图片变小而重新分页**。`fitsAt` 读的是测量克隆的连续流，模型说 page 0；最终 PDF 由活 DOM 的打印分页决定，仍是 page 1（第 2 页）。两者分叉，所以任何“在旧页坐标里缩图”的补丁都不会反映到输出。

## 正确的修法

必须让**活打印树**在缩放后重新分页，而不是只刷新测量克隆。可选路径：

1. 在 `optimizePdfPagination` 结束后，如果本次有 gallery 缩放，克隆整个 print root，替换原节点，再跑一轮分页（需要把 `state`/`cleanups` 迁移到新 root）。
2. 或者把“是否需要缩行”提前到打印分页之前，用一次预测量决定 scale，再生成最终树；不在已分页的树上做事后压缩。

这两条都属于分页主流程改造，不能再用局部补丁。当前 `src/pdf-pagination.js` 已恢复到提交状态，`git diff src/` 为空；`main.js` 已重建，硬链接恢复。

## 修复结果（方案 2：打印前预计算）

在 `runImagePass` 里新增一段“预压缩”：当画廊行的 `residual` 落在 `[0, 12)` px 时，按 `deficit = 20 + residual` 直接算出一个固定 scale（上限仍是 30%），一次性应用、不回滚，再让最终打印树用缩小后的尺寸分页。它不进入 `attemptExactFit`，因此没有在旧页坐标里做二分。
