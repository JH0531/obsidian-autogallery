# 嵌套作用域

> 一张图只属于离它最近的那个容器：列表项、表格单元格、callout，最后才是正文。容器不同，插件能做的事情也不同。

## 列表：同项可并排，绝不跨项

- 同一条目里的两张图可以并排：
  ![](assets/ratio/ratio-3x2.svg)
  ![](assets/ratio/ratio-1x1.svg)
- 换一条目就是新的一行：
  ![](assets/ratio/ratio-4x3.svg)

列表里的单图默认靠左、按块布局，不浮动；也不提供画廊手柄 —— 项目符号会让「行」的边界变得含糊。跨条目的图片永远不会并排，哪怕源码里紧挨着。

## 表格：只认裁剪与排除

| 单元格内容 | 结果 |
| --- | --- |
| ![[05-falls.jpg\|瀑布方形\|ag:crop=1:1]] | 只应用裁剪，宽度仍由表格决定 |
| ![[03-valley.jpg\|谷地\|ag:exclude]] | 完全交给 Obsidian |
| 手写 `ag:width` / `ag:side` | 不生效 |

表格里的管道符必须写成 `\|`，否则参数会被当成图注的一部分。插件的裁剪用 `object-view-box` 实现，旧内核会自动退回 `object-fit`。

## Callout：只认领，不装饰

callout 里的图片保持 Obsidian 原生样式：不并排、不加图注、不显示任何手柄。

原因很直接 —— callout 在实时预览里不是一个可编辑的块，插件写进去的几何读者无法调整，所以选择完全不接管。在 callout 里写 `ag:` 参数不会有任何效果，也不会报错；这是本插件唯一一处「静默忽略」的参数场景。

## 能力矩阵

| 容器 | 宽度/浮动 | 画廊 | 裁剪 | 手柄 |
| --- | --- | --- | --- | --- |
| 正文 | 是 | 是 | 是 | 是 |
| 列表项 | 块布局，可写宽度 | 同项内可并排 | 是 | 否 |
| 表格单元格 | 否 | 否 | 是 | 仅实时预览的操作按钮 |
| Callout | 否 | 否 | 否 | 否 |
