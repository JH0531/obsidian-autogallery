# 导入与导出

> 模板规则写在 `.json` 或 `.js` 文件里，通过设置页「配置管理」导入。导入是覆盖式更新，整份校验，要么全成要么全不动。

## 文件格式

```json
{
  "id": "wide",
  "name": "wide",
  "floatAlignment": "alternate",
  "rules": [
    { "ratioRange": "[0.75,1.35]", "width": 0.68, "layout": "auto", "side": "auto" },
    { "ratioRange": "(1.35,5]", "width": "0.55 + 0.1 * Math.log(r)", "layout": "auto", "side": "auto" },
    { "ratioRange": "[0.2,0.75)", "width": "Math.max(0.32, 0.3 + 0.2 * r)", "layout": "float", "side": "left" }
  ]
}
```

把这段存成 `.json`，在设置页「配置管理 → 导入配置」选中即可。文件里也可以放一个数组，一次导入多个模板。

`id` 可以省略，省略时取文件名；`rules` 写成空数组时按 `auto` 处理。

## 覆盖式更新

| 情况 | 结果 |
| --- | --- |
| 与已有模板同 `id` | 整份替换 |
| 文件里没提到的模板 | 保持不变 |
| `id` 是内置的 `auto` | 永远跳过，不会被覆盖 |
| 规则条数被静默丢弃 | 导入后要回设置页核对条数 |

最后一条值得单独说：**已经存进配置的非法规则会被静默丢弃**，而不是报错。所以导入完成后，在同一个面板里看一遍规则条数是否与文件一致；少了就是有表达式没过校验。

## 整份校验

任意一条模板非法时，整个文件被拒绝导入，设置不会部分写入。这样不会出现「导了一半，前两条生效后两条没生效」的状态。

## 外部配置文件

设置项 `externalProfilePath` 可以指向一个库外的配置文件。适用于「模板跟着团队仓库走，而不是跟着个人库走」的场景：

- 路径可以写绝对路径，也可以写相对库根目录的路径。
- 文件不存在或读取失败时，回落到上次成功导入的配置，不会把模板清空。
- 导出时可以选择写入这个路径，或直接下载到系统下载目录。

## 导出

「导出全部」把当前所有模板写成一个文件，格式与导入完全一致 —— 因此可以把导出的文件当模板直接改，再导回来。
