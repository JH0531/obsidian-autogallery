# 五个核心概念

> 插件的所有行为都从这五条推出。理解它们之后，绝大多数「为什么没生效」都能自己回答。

## 一、分组看源码，不看屏幕

插件读的是**源文本里图片所在的行**，不是渲染后的 DOM。所以滚动、缩放、切换视图都不会改变谁和谁是一组。

阅读视图会把空行折叠掉，画面上的间距看起来一样；但源码里 0 个空行、1 个空行、2 个空行是三种不同的写法，第三种已经到上限。判断分组时数空行，别靠视觉留白。

## 二、两张以上连续图片一定是画廊

只要同一组里有两张及以上，它们就进入画廊：共用一条行高，列宽按比例分配。此时**逐张写的 `ag:layout`、`ag:width`、`ag:side` 全部被忽略** —— 一行是一个整体。

要让某张图单独控制，先把它移出这一组：用正文或标题断开，或者写 `ag:isolate`。

## 三、单图的宽度由比例算出

不写任何参数时，单图的栏宽百分比是比例的分段幂函数：方图约四成（39%），横图接近满栏，竖图只剩三成左右。两条分界线分别决定「居中还是浮动」和「浮到左还是右」。

三个旋钮可以整体平移这条曲线：设置页的「栏宽增益」「中位比例」，以及模板规则。

## 四、越靠近图片的声明优先级越高

从低到高：

1. 设置页的全局参数（`floatMax`、`mobileBreakpoint` 等）
2. 当前模板的规则
3. 图片自己的 `ag:` 参数写死的那一项

所以模板再宽，一张写了 `ag:width=40%` 的图仍是 40%。反过来，模板只能影响「没写参数、布局为 auto」的图。

## 五、容器决定能力

同样一张图，放在正文、列表项、表格单元格、callout 里，能用的功能依次减少：

| 容器 | 宽度/浮动 | 画廊 | 裁剪 | 手柄 |
| --- | --- | --- | --- | --- |
| 正文 | 是 | 是 | 是 | 是 |
| 列表项 | 块布局，可写宽度 | 同项内可并排 | 是 | 否 |
| 表格单元格 | 否 | 否 | 是 | 仅实时预览的操作按钮 |
| Callout | 否 | 否 | 否 | 否 |

这不是遗漏，而是故意的：容器越复杂，可安全调整的几何越少。细节见[[12-嵌套作用域]]。
